# REST API TextDiff

TextDiff сравнивает две группы текстов по лексике. Через API это делается в три шага: создать задачу, дождаться статуса
`done`, забрать результат. Интерактивная документация (Swagger UI) — `/api/docs`, схема OpenAPI — `/api/openapi.json`.
Весь API работает только для вошедших пользователей.

## Быстрая справка

| Метод | Путь | Что делает | Успех | Ошибки |
| --- | --- | --- | --- | --- |
| `POST` | `/api/tasks` | создаёт задачу и запускает расчёт в фоне | `202` | `401`, `422` |
| `GET` | `/api/tasks` | список своих задач (до 100), фильтр `?status=` | `200` | `401` |
| `GET` | `/api/tasks/{id}` | статус своей задачи | `200` | `401`, `404` |
| `GET` | `/api/tasks/{id}/result` | результат расчёта | `200` | `401`, `404`, `409` |

## Доступ

* Аутентификация сессионная (`django_auth`): API проверяет ту же cookie, которую браузер получает при входе на `/accounts/login/`.
* Без входа любой запрос получает `401`.
* Для `POST` нужен заголовок `X-CSRFToken` со значением cookie `csrftoken` (пример — в конце документа).
* Каждый пользователь видит только свои задачи. Чужая задача отвечает `404`, а не `403`: посторонний не должен узнать,
  что задача с таким номером существует (ADR-005).

## Задача и её статусы

Расчёт идёт в фоне (ADR-004), поэтому `POST` отвечает сразу, а результат появляется позже.

| Статус | Значение |
| --- | --- |
| `created` | задача записана, расчёт ещё не начался |
| `queued` | задача в очереди RQ (только при `USE_QUEUE=1`) |
| `running` | идёт расчёт |
| `done` | расчёт завершён, результат готов |
| `failed` | расчёт не удался, причина в поле `error` |

Переходы: `created → running → done` или `failed`; в режиме очереди перед `running` добавляется `queued`.

## POST /api/tasks — создать задачу

Тело запроса:

```json
{
  "name": "Отзывы: позитив и негатив",
  "params": {
    "rows": [
      {"text": "дом дом дом дом", "group": "A"},
      {"text": "кот кот кот", "group": "A"},
      {"text": "кот сидел на окне", "group": "B"},
      {"text": "солнце светило весь день", "group": "B"}
    ],
    "test": "permutation",
    "top_n": 3,
    "n_permutations": 1000,
    "seed": 0
  }
}
```

Параметры `params`:

| Поле | По умолчанию | Ограничения |
| --- | --- | --- |
| `rows` | — (обязательно) | от 2 до 50 000 строк; ровно две разные группы; в каждом тексте хотя бы одно слово |
| `rows[].text` | — | от 1 до 200 000 символов |
| `rows[].group` | — | от 1 до 100 символов |
| `test` | `mannwhitney` | `mannwhitney`, `ttest` или `permutation` |
| `top_n` | `20` | от 1 до 200 |
| `n_permutations` | `1000` | от 1 до 200 000, используется только в `permutation` |
| `seed` | `0` | любое целое; один `seed` даёт один результат |

Для `permutation` действует граница нагрузки: строк × перестановок не больше 40 000 000.

Ответ `202`:

```json
{"id": 7, "name": "Отзывы: позитив и негатив", "status": "created", "core_version": "", "error": ""}
```

Строки `rows` в базе не хранятся: сервер сохраняет их файлом `MEDIA_ROOT/inputs/task_<id>.csv`, а в базе остаются
настройки анализа и путь к файлу (ADR-006).

## GET /api/tasks и GET /api/tasks/{id}

Возвращают те же поля, что и ответ на создание: `id`, `name`, `status`, `core_version`, `error`.
`GET /api/tasks?status=done` оставляет только готовые задачи. Результат расчёта в эти ответы не входит.

## GET /api/tasks/{id}/result — результат

Пока задача не в статусе `done`, ответ `409`:

```json
{"detail": "Задача ещё не завершена: статус running"}
```

Когда задача готова, ответ `200`. Пример для запроса выше (на нём же построен эталон: четыре текста, `permutation`):

```json
{
  "id": 7,
  "status": "done",
  "result": {
    "n_texts": 4,
    "groups": {
      "A": {"n_texts": 2, "avg_len_words": 3.5, "avg_ttr": 0.29166666666666663, "avg_word_len": 3.0},
      "B": {"n_texts": 2, "avg_len_words": 4.0, "avg_ttr": 1.0, "avg_word_len": 4.375}
    },
    "test": "permutation",
    "statistic": 0.7083333333333334,
    "pvalue": 0.3333333333333333,
    "top_words": [["дом", 4], ["кот", 4], ["сидел", 1]],
    "permutations_used": 6,
    "permutations_exact": true,
    "core_version": "0.1.0",
    "elapsed_sec": 0.0004
  }
}
```

Что означают поля результата:

| Поле | Значение |
| --- | --- |
| `groups.<имя>.n_texts` | сколько текстов в группе |
| `groups.<имя>.avg_len_words` | средняя длина текста в словах |
| `groups.<имя>.avg_ttr` | средний TTR: уникальные слова ÷ все слова (подробнее в `docs/architecture.md`, разделы 7 и 12) |
| `groups.<имя>.avg_word_len` | средняя длина слова в символах |
| `statistic`, `pvalue` | статистика и p-value выбранного теста; `null`, если посчитать нельзя |
| `top_words` | пары «слово — частота», не больше `top_n` |
| `permutations_used` | сколько разбиений использовано (только у `permutation`) |
| `permutations_exact` | `true` — перебраны все разбиения, `false` — случайная выборка (только у `permutation`) |
| `core_version`, `elapsed_sec` | версия ядра и время расчёта в секундах (зависит от машины) |

В примере разбиений ровно 6 (`C(4,2) = 6`), поэтому перебор точный, а `pvalue = 2/6`.

Важно при чтении `avg_ttr`: TTR падает, когда текст длиннее. Если средняя длина текстов в группах (`avg_len_words`) сильно
различается, разницу в TTR нельзя целиком относить на счёт разнообразия лексики.

## Формат ошибок

Ошибки нашего кода имеют вид `{"detail": "текст"}`.

| Код | Когда | Пример |
| --- | --- | --- |
| `401` | не выполнен вход | аноним вызвал любой эндпоинт |
| `404` | задачи нет или она чужая | `GET /api/tasks/999` |
| `409` | результат запрошен до завершения | статус `running` |
| `422` | вход не прошёл проверку, задача не создаётся | см. таблицу ниже |
| `400` | тело запроса больше 2,5 МБ (ограничение самого Django, формат ответа не наш) | очень большой `rows` |

Причины `422`:

| Причина | Текст в `detail` (начало) |
| --- | --- |
| групп не две | «Нужно ровно две группы текстов для сравнения, найдено: N» |
| в тексте нет слов | «Строка K: в тексте нет ни одного слова» (K — номер строки в CSV, заголовок — строка 1) |
| расчёт слишком тяжёлый | «Слишком большой расчёт: строк × перестановок = …» |
| неизвестный `test`, `top_n` вне 1…200 и т.п. | сообщение схемы с именем поля |

Если расчёт упал уже после создания, задача получает статус `failed`, а причина лежит в поле `error`
(например, «Входной файл задачи не найден»).

## Пример на Python

Нужен пакет `requests`. Скрипт входит под своим пользователем, создаёт задачу и ждёт результат.

```python
import time

import requests

BASE = "http://127.0.0.1:8000"
session = requests.Session()

session.get(f"{BASE}/accounts/login/")  # получаем cookie csrftoken
session.post(
    f"{BASE}/accounts/login/",
    data={"username": "user", "password": "пароль", "csrfmiddlewaretoken": session.cookies["csrftoken"]},
)

payload = {
    "name": "пример",
    "params": {
        "rows": [
            {"text": "дом дом дом дом", "group": "A"},
            {"text": "кот кот кот", "group": "A"},
            {"text": "кот сидел на окне", "group": "B"},
            {"text": "солнце светило весь день", "group": "B"},
        ],
        "test": "permutation",
    },
}
created = session.post(f"{BASE}/api/tasks", json=payload, headers={"X-CSRFToken": session.cookies["csrftoken"]})
task_id = created.json()["id"]

while True:
    status = session.get(f"{BASE}/api/tasks/{task_id}").json()["status"]
    if status in ("done", "failed"):
        break
    time.sleep(1)

print(session.get(f"{BASE}/api/tasks/{task_id}/result").json())
```
