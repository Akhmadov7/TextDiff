# ADR-003. Формат входных данных и синхронное выполнение на заезде 1

**Статус:** принято

**Контекст**
AGENTS.md требует: вход валидируется pydantic-схемой до запуска расчёта, core не знает
про HTTP/БД, статус задачи меняется только в services.execute_task. На заезде 1 очередь
(RQ + Redis) ещё не подключена — согласно README стартера, расчёт может выполняться синхронно
до второго интенсива.

**Рассмотренные варианты**
1. Принимать сырой текстовый файл (.txt) на каждую строку/документ отдельно, группы —
   по имени файла/папке. Плюс: не нужен парсинг CSV. Минус: неудобная форма загрузки
   для сравнения двух групп, сложнее валидировать.
2. Принимать один CSV с колонками text/group (имена настраиваются в форме),
   парсинг — в web/services.py, в core передаётся уже готовый список строк.
   Плюс: соответствует формату темы №5 («CSV-файл, выбор столбцов»), один файл на задачу,
   проще валидация pydantic-схемой (core/schemas.py: TextDiffParams).

**Решение**
Выбран вариант 2. Парсинг CSV — в services.py (не в core, чтобы core оставался чистым
и не знал о файлах). Расчёт выполняется синхронно в create_task/execute_task; переход на
RQ-очередь (jobs.enqueue_task) без изменения контракта core.run() выполняется на заезде 2.

**Последствия**
Ядро можно тестировать локально через `python -m core input.json` без Django уже сейчас.
Синхронное исполнение ограничивает размер входа на заезде 1 (иначе — таймаут запроса) —
это осознанное ограничение, снимается очередью на межсессии 2 / заезде 2.
