# ADR-004. Поток, а не очередь

**Статус:** принято
**Дата:** 2026-09-30

## Контекст
Расчёт шёл прямо в запросе: `web/services.py` вызывал `execute_task` синхронно, и на 4000 текстах
(10 000 перестановок) страница «висела» около 13 секунд — замер в README. Страница задачи не обновляла статус сама. ADR-003 обещал
синхронный расчёт только «до заезда 2», а очередь (RQ + Redis, `web/jobs.py`) пока требует
отдельного процесса-воркера и Redis.

## Рассмотренные варианты
1. **Оставить синхронный расчёт** — проще всего, но запрос блокируется на время расчёта
   и на большом входе упирается в таймаут.
2. **Очередь RQ + Redis** — правильно для продакшена, но нужен Redis и воркер; для учебного
   объёма это лишняя инфраструктура (включается флагом `USE_QUEUE=1`, код уже есть).
3. **Поток (`threading.Thread`)** в том же процессе сервера — запрос отвечает сразу,
   расчёт идёт в фоне, не нужно ничего запускать дополнительно.

## Решение
Выбран вариант 3: при `USE_QUEUE=0` `create_task` запускает `execute_task` в отдельном потоке
и сразу возвращает задачу со статусом `created`. Статус меняется сам: `created → running → done`
(или `failed`). Страница `detail.html` перезагружается (`meta refresh`), пока статус не `done`
и не `failed`. Контракт `core.run()` не менялся.

## Последствия
Страница открывается сразу, статус обновляется без участия пользователя. Очередь остаётся
запасным вариантом (`USE_QUEUE=1`).
Риск: поток живёт внутри процесса сервера. Если сервер перезапустили во время расчёта, поток
погибает, а задача навсегда остаётся в статусе «running» — никто её не доведёт до конца
и не пометит `failed`. Очередь эту проблему решает (задача хранится в Redis), поэтому для
настоящей нагрузки потребуется переход на неё. Границы входа (см. README) ограничивают
длительность расчёта.

**Дополнение 02.10 — тесты.** Сценарный тест изредка падал (примерно в одном запуске из восьми): тест и фоновый поток
одновременно работали с базой данных. Теперь в тестах расчёт идёт без потока: настройка `TASKS_SYNC=1`
(`tests/conftest.py`, автоматически для всех тестов в `tests/`) заставляет `create_task` вызвать `execute_task` сразу, в том же потоке.
Что при обычной работе `create_task` действительно запускает поток (`daemon=True`) и не ждёт расчёта, проверяет отдельный тест
`test_without_sync_flag_calculation_goes_to_background_thread` с подменой `Thread`. Для сервера `TASKS_SYNC` остаётся
выключенным.
