# ADR-001. Выбор стека: Django + Django Ninja

**Статус:** принято
**Дата:** 2026-09-03

## Контекст
Нас четверо, опыт с веб-разработкой у всех небольшой, срок — два месяца с двумя интенсивами. Проект должен уметь: хранить
пользователей и их задачи, принимать CSV через форму, отдавать результат по API с понятной документацией и считать
статистику в Python (scipy). Преподаватель знает Django, поэтому разбирать ошибки с ним проще.

## Рассмотренные варианты
1. **Django + Django Ninja.** Плюсы: вход, пользователи, админка, ORM и миграции уже есть; Ninja даёт схемы на Pydantic и
   страницу Swagger без отдельной настройки. Минусы: у Django много соглашений, и нам пришлось их учить; для небольшого
   сервиса он тяжелее, чем нужно.
2. **FastAPI + SQLAlchemy.** Плюсы: прозрачнее и быстрее, асинхронность из коробки. Минусы: вход, админку, миграции и HTML-формы
   пришлось бы делать самим, а это время, которого у нас нет.
3. **Flask.** Плюсы: самый простой старт. Минусы: всё то же, что у FastAPI, и автодокументации API нет.

## Решение
Взяли Django + Django Ninja: время тратим на ядро и архитектуру, а не на вход пользователей и админку.

## Последствия
Платим тем, что подчиняемся структуре Django (приложения, миграции, настройки) и тащим весь фреймворк ради небольшого
сервиса. Фоновый расчёт в Django из коробки не работает, поэтому пришлось отдельно решать про поток и очередь (ADR-004).
Переехать на другой стек позже дорого: модели и шаблоны привязаны к Django, а ядро (`core/`) от него не зависит и
перенесётся без изменений.
