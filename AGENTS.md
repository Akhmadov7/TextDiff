# AGENTS.md — контекст для AI-ассистента (Claude, Codex, Cursor, Gemini, ChatGPT)

Прочитай перед тем, как предлагать код. Это учебный проект курса «Архитектура и проектирование веб-приложений».

## Что это
Веб-сервис с вычислительным ядром: пользователь создаёт задачу, расчёт выполняется (синхронно на заезде 1, через очередь RQ на заезде 2), результат сохраняется и показывается с графиком.

## Стек (не менять без ADR)
Python 3.14 (минимум 3.12), Django 5.x, Django Ninja (API), pydantic (валидация), SQLite → PostgreSQL, Redis + RQ (очередь), pytest, ruff, Docker.

## Архитектурные ограничения — ОБЯЗАТЕЛЬНЫ
1. `core/` не импортирует Django, не обращается к БД и HTTP. Только `run(params: dict) -> dict` и чистые функции.
2. Views и API не содержат бизнес-логики и не вызывают `core` напрямую — только через `web/services.py`.
3. Статусы задачи меняются только в `services.execute_task` / `jobs.enqueue_task`.
4. Вход пользователя валидируется pydantic-схемой ДО запуска расчёта. Никакого `eval`/`exec` на пользовательских строках.
5. Секреты — только в `.env` (в git не попадает). Никаких ключей и паролей в коде.
6. Большие результаты — в файлы (`MEDIA_ROOT`), в JSON-поле — только метаданные и выборка ≤200 точек для графика.
7. Любое изменение схемы БД — через миграцию (`makemigrations`), не руками.

## Как работать
- Малые шаги: одно изменение — один тест — один коммит.
- Перед тем как предложить код: назови, какой слой меняешь и почему это его ответственность.
- Если предлагаешь новую зависимость — скажи, зачем, и что будет без неё.
- Тесты: `pytest -q`; стиль: `ruff check .`. Не «чини» падающий тест, меняя проверку, — сначала объясни, почему он падает.
- Не используй устаревшие API Django (< 4.2) и не выдумывай пакеты: если не уверен, что пакет существует, скажи.
